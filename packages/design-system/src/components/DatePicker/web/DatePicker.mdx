# DatePicker

A month-view calendar for picking a date. Pick a day by clicking it; move between months (and
across years) with the previous/next arrows. It renders inline, or in a popover opened from a
`trigger` you pass, such as a Button.

**Web only.**

For a text field where people can also type the date, use
[FormControl.DatePicker](/docs/forms-formcontrol-datepicker--docs).

## Usage

```tsx
function GameDatePicker() {
  const [date, setDate] = useState<CalendarDate | null>('2026-03-10');

  return <DatePicker value={date} onChange={setDate} label="Choose a game date" />;
}
```

- **Controlled:** pass `value` (`null` for no selection) and `onChange`
- **Uncontrolled:** pass `defaultValue` (or nothing) and optionally `onChange`
- Opens on the selected date's month, or the current month when nothing is selected
- Use `min` / `max` to limit the calendar, e.g. to a season. Days outside them are disabled, and
  the arrows stop at their months. The stopped arrow is dimmed and shows a tooltip explaining why;
  set the text with `minMessage` / `maxMessage`, e.g. "No games to display before November 2025"
- Weeks start on Sunday. Days from the neighboring months pad out the first and last weeks; they're
  dimmed and not selectable

### In a popover: `trigger`

Pass any element as `trigger` and the calendar opens in a popover when it's clicked. The popover
closes when a day is picked, so there's no open state to manage.

```tsx
<DatePicker
  value={date}
  onChange={setDate}
  label="Choose a game date"
  trigger={
    <Button variant="outlined" icon={<CalendarIcon />} iconPosition="start">
      {formatLongDate(date)}
    </Button>
  }
/>
```

- `placement` (default `bottom`) sets which side of the trigger the popover opens on
- `portalRoot` renders the popover into a given element instead of `document.body`, e.g. inside a
  modal
- Sizing and padding match the design, so no class overrides are needed

### Dates are `YYYY-MM-DD` strings, not `Date` objects

Values are calendar dates like `'2026-03-10'`, with no time or timezone. A `Date` is an instant, so
the day it falls on depends on where it's viewed: `new Date('2026-03-10')` is March 9 in Minnesota.
Strings are the same day on the server and in every browser, and they compare with `===`.

If you have a `Date`, read the date from its local fields:

```ts
const toCalendarDate = (d: Date) =>
  `${d.getFullYear()}-${String(d.getMonth() + 1).padStart(2, '0')}-${String(d.getDate()).padStart(2, '0')}` as CalendarDate;
```

## Not supported yet

- Picking a month or year from a list (only the previous/next arrows)
- Disabling individual days (other than through `min` / `max`)
- Date ranges
- Localized month and weekday names, or a Monday week start
- Anchoring the popover to an element other than the trigger

## Accessibility

- The calendar is a labeled group containing a grid; the month heading is announced when it changes
- At `min` / `max` the arrow is `aria-disabled` rather than `disabled`, so it stays focusable and
  its tooltip can be reached by keyboard and hover
- The grid is one Tab stop. Arrow keys move a day or week, crossing into the next or previous month;
  Page Up / Page Down move a month. Enter or Space selects
- Each day is announced with its full date, e.g. "Tuesday, March 10, 2026". Today is marked with
  `aria-current="date"`

With a `trigger`:

- The trigger is announced as opening a dialog, with its expanded state. When it shows only the
  date, `label` is added as its description: "March 10, 2026, button, Choose a game date"
- The popover is a modal dialog named by `label`. It opens with focus on the selected day (or
  today), and focus stays inside until it closes
- Picking a day, a single Escape (even while an arrow's tooltip is showing) or clicking outside
  closes it and returns focus to the trigger
