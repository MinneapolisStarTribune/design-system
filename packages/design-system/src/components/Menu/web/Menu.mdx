# Menu

`Menu` shows a short list of actions or links next to the element that triggered it, for example an account menu, a table row's "more actions" button, or a bulk-actions button. It uses the shared internal surface that also powers `Popover`, so it has the same surface, pointer, and dismiss behavior. It closes when the user selects an item, clicks outside, or presses Escape or Tab.

[Figma Comps](https://www.figma.com/design/f8DSKwKjG4MsSqmA59v1um/Core-Components?node-id=66-508)

## Anatomy

1. **Container** — the rounded popover surface that holds the items.
2. **Pointer** — the arrow that points at the anchor. It can be pinned or hidden.
3. **Item** — one row. It renders a `<button>`, or an `<a>` when `href` is set.
4. **Start icon (optional)** — shown before the label.
5. **End icon (optional)** — pushed to the right, for example an external-link arrow.
6. **Divider (optional)** — separates groups of items.

## Usage

- Use a menu for a handful of actions or links tied to one element
- Don't use a menu to pick a form value; use `Select`
- Don't use a menu for rich content such as text, forms, or headings; use `Popover`
- Keep labels short and start them with a verb, for example "Edit" or "Pause Account"
- Group related items and separate the groups with `Menu.Divider`
- To show items only in some states, render them conditionally (`{status === 'active' && <Menu.Item />}`). Use `disabled` only when the user should see that the action exists
- Menu doesn't render its trigger. Keep the trigger element in state and pass it as `anchorEl`

## Positioning

`anchorOrigin` and `transformOrigin` work like MUI's: each is a `{ vertical, horizontal }` point, and the menu moves so its `transformOrigin` sits on the anchor's `anchorOrigin`.

```tsx
<Menu.Root
  anchorOrigin={{ vertical: 'bottom', horizontal: 'right' }}
  transformOrigin={{ vertical: 'top', horizontal: 'right' }}
/>
```

When the origins sit on opposite edges (anchor bottom and menu top, anchor right and menu left), the menu opens beside the anchor with the pointer. If that side runs out of room, it flips to the other side. Any other pair, such as top-left to top-left, puts the menu over the anchor. The pointer is then hidden. Instead of flipping, the menu slides up or down to stay on screen.

While the menu is open, page scroll is locked, so the menu can't drift away from its anchor. Pressing outside the menu closes it; that press doesn't reach the element underneath.

For example, opening above with right edges aligned (`anchorOrigin` top right, `transformOrigin` bottom right) and `arrowOffset="end"` pins the pointer 16px from the menu's right edge. If the menu has to shift sideways to fit on screen, a pinned pointer goes back to aiming at the anchor. Set `hideArrow` to remove the pointer.

## Example

```tsx
const [anchorEl, setAnchorEl] = useState<HTMLElement | null>(null);

<Button
  aria-label="Row actions"
  aria-haspopup="menu"
  aria-expanded={anchorEl !== null}
  icon={<MenuVerticalIcon />}
  variant="ghost"
  onClick={(event) => setAnchorEl(event.currentTarget)}
/>

<Menu.Root
  anchorEl={anchorEl}
  open={anchorEl !== null}
  onClose={() => setAnchorEl(null)}
  anchorOrigin={{ vertical: 'bottom', horizontal: 'right' }}
  transformOrigin={{ vertical: 'top', horizontal: 'right' }}
  aria-label="Row actions"
>
  <Menu.Item onClick={onEdit}>
    <Menu.ItemIcon><EditIcon /></Menu.ItemIcon>
    Edit
  </Menu.Item>
  {status === 'active' && (
    <Menu.Item onClick={onPause}>
      <Menu.ItemIcon><PauseIcon /></Menu.ItemIcon>
      Pause Account
    </Menu.Item>
  )}
  <Menu.Divider />
  <Menu.Item href="https://varsity.startribune.com/" target="_blank" rel="noopener noreferrer">
    <Menu.ItemIcon><HelpIcon color="brand-01" /></Menu.ItemIcon>
    Help Center
    <Menu.ItemIcon position="end"><ArrowDiagonalIcon /></Menu.ItemIcon>
  </Menu.Item>
</Menu.Root>
```

The menu follows the app's light or dark theme. The surface, text, default icon color, dividers, and hover state all switch with it.

Icons keep their own color. Pass a named color such as `brand-01`, which resolves per brand and theme (green for Star Tribune, blue for Varsity), or any CSS color through `style`.

## Accessibility

### Keyboard Navigation

- The first enabled item receives focus when the menu opens
- **Arrow Down / Arrow Up** move between items and wrap around. Disabled items are skipped
- **Home / End** jump to the first or last item
- **Enter** selects the focused item. **Space** also selects button items; links follow the browser's default
- **Escape**, **Tab**, or a click outside closes the menu, and focus returns to the anchor

### Screen Readers

- The menu uses the `menu` ARIA role, and each item uses `menuitem`
- Give the menu an `aria-label` or `aria-labelledby`
- Icons are decorative and hidden from screen readers, so the label has to make sense on its own
- Add `aria-haspopup="menu"` and `aria-expanded` to your trigger. Menu doesn't render the trigger, so it can't add them for you
