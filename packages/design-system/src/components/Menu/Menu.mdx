# Menu

`Menu` shows a short list of actions or links next to the element that triggered it, for example an account menu, a table row's "more actions" button, or a bulk-actions button. It uses the shared internal surface that also powers `Popover`, so it has the same surface, pointer, and dismiss behavior.

[Figma Comps](https://www.figma.com/design/f8DSKwKjG4MsSqmA59v1um/Core-Components?node-id=66-508)

## Anatomy

1. **Container** (`Menu.Root`): the rounded popover surface that holds the items. It renders `trigger` or positions against `anchorEl`, and handles dismiss, focus, and arrow-key navigation.
2. **Pointer**: the arrow that points at the anchor. It can be pinned or hidden.
3. **Item** (`Menu.Item`): one row. It renders a `<button>`, or an `<a>` when `href` is set.
4. **Start icon (optional)** (`Menu.ItemIcon`): shown before the label.
5. **End icon (optional)** (`Menu.ItemIcon position="end"`): pushed to the right, for example an external-link arrow.
6. **Divider (optional)** (`Menu.Divider`): separates groups of items.

## Usage

- Use a menu for a handful of actions or links tied to one element
- Don't use a menu to pick a form value; use `Select`
- Don't use a menu for rich content such as text, forms, or headings; use `Popover`
- Keep labels short and start them with a verb, for example "Edit" or "Pause Account"
- Group related items and separate the groups with `Menu.Divider`
- To show items only in some states, render them conditionally (`{status === 'active' && <Menu.Item />}`). Use `disabled` only when the user should see that the action exists
- Pass `trigger` and the menu renders it, toggles on click, and sets `aria-haspopup`, `aria-expanded`, and `aria-controls`. The trigger must be a single element that accepts a ref
- Pass `anchorEl` instead when you manage the anchor yourself, for example to open the menu from a table row. Keep the element in state and set the trigger's ARIA attributes yourself

### Theme and icon color

The menu follows the app's light or dark theme. The surface, text, default icon color, dividers, and hover state all switch with it.

Icons keep their own color. Pass a named color such as `brand-01`, which resolves per brand and theme (green for Star Tribune, blue for Varsity), or any CSS color through `style`.

## Positioning

`placement` sets the side of the anchor the menu opens on: `top`, `right`, `bottom`, or `left`. Add `-start` or `-end` to align the menu's start or end edge with the anchor's; leave it off to center the menu on the anchor.

```tsx
<Menu.Root placement="bottom-end" />
```

If the chosen side runs out of room, the menu flips to the opposite side.

While the menu is open, page scroll is locked, so the menu can't drift away from its anchor. Pressing outside the menu closes it; that press doesn't reach the element underneath.

### Responsive

`placement` and `arrowOffset` also take an object keyed by breakpoint. Each key applies from that breakpoint up. Breakpoints below the smallest key use the default.

```tsx
<Menu.Root placement={{ small: 'right', large: 'top' }} arrowOffset={{ large: 'end' }} />
```

## Accessibility

### Keyboard Navigation

- The first enabled item receives focus when the menu opens
- **Arrow Down / Arrow Up** move between items and wrap around. Disabled items are skipped
- **Home / End** jump to the first or last item
- **Enter** selects the focused item. **Space** also selects button items; links follow the browser's default
- **Escape**, **Tab**, or a click outside closes the menu, and focus returns to the anchor

### Screen Readers

- The menu uses the `menu` ARIA role, and each item uses `menuitem`
- Give the menu an `aria-label` or `aria-labelledby`
- Icons are decorative and hidden from screen readers, so the label has to make sense on its own
- With `anchorEl`, add `aria-haspopup="menu"` and `aria-expanded` to your trigger yourself. With `trigger`, Menu sets them for you
