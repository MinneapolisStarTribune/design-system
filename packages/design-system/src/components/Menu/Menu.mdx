# Menu

`Menu` shows a short list of actions or links next to the element that opened it, such as an account menu or a table row's "more actions" button.

[Figma Comps](https://www.figma.com/design/f8DSKwKjG4MsSqmA59v1um/Core-Components?node-id=66-508)

## Anatomy

1. **Container** (`Menu.Root`): the rounded box that holds the items.
2. **Arrow**: points at the trigger. It can be fixed in place or hidden.
3. **Item** (`Menu.Item`): one row. It renders a `<button>`, or an `<a>` when `href` is set.
4. **Start icon (optional)** (`Menu.ItemIcon`): shown before the label.
5. **End icon (optional)** (`Menu.ItemIcon position="end"`): pushed to the right, for example an external-link arrow.
6. **Divider (optional)** (`Menu.Divider`): separates groups of items.

## Usage

- Don't use a menu to pick a form value; use `Select`, or `MultiSelect` for several values
- Don't use a menu for rich content such as text, forms, or headings; use `Popover`
- Keep labels short and start them with a verb, for example "Edit" or "Pause Account"
- Group related items and separate the groups with `Menu.Divider`
- Hide items that don't apply by not rendering them, for example `{status === 'active' && <Menu.Item />}`
- Use `disabled` when users should see an action they can't use yet

### Theme and icon color

The menu follows the app's light or dark theme. The background, text, default icon color, dividers, and hover state all switch with it.

Icons don't take the text color. Set it with a named `color` such as `brand-01`, which changes with brand and theme (green for Star Tribune, blue for Varsity), or any CSS color through `style`. A class can't change the color of a design-system icon, because the icon sets it inline.

## Positioning

`placement` sets the side of the trigger the menu opens on: `top`, `right`, `bottom`, or `left`. Add `-start` to line up the left edges of the menu and trigger, or `-end` to line up the right edges (top and bottom edges for `left` and `right` menus). Leave it off to center the menu on the trigger.

```tsx
<Menu.Root placement="bottom-end" />
```

Align the menu with the side of the screen the trigger sits on. For example, use `bottom-end` for a "more actions" button at the right edge of a table row, so the menu opens inward.

If the chosen side runs out of room, the menu flips to the opposite side. A `left` or `right` menu that fits on neither side opens below or above the trigger instead. When no side has enough room, the menu shrinks to fit and its items scroll.

By default, the page can't scroll while the menu is open. Scrollable areas inside the page, such as a table, still scroll, and the menu follows its trigger. Set `lockScroll={false}` to let the page scroll too.

### Responsive

`placement` and `arrowPosition` can change by screen size. Pass an object with any of these keys: `small` (0px and up), `medium` (768px and up), and `large` (1160px and up). Each value applies from its screen size up. Screens below the smallest key use the default.

```tsx
<Menu.Root placement={{ small: 'right', large: 'top' }} arrowPosition={{ large: 'end' }} />
```

## Arrow

By default, the arrow points at the center of the trigger and stays at least 16px from the menu's rounded corners. Use `arrowPosition` only when a design needs the arrow in a fixed place. `'start'` or `'end'` puts it 16px from that edge of the menu (left or right; top or bottom for `left` and `right` menus), and `'center'` puts it in the middle.

For example, `placement="top-end"` with `arrowPosition="end"` puts the arrow 16px from the menu's right edge. If the menu has to shift sideways to fit on screen, a fixed arrow goes back to pointing at the trigger.

## Accessibility

### Keyboard Navigation

- **Enter**, **Space**, or **Arrow Down** on the trigger opens the menu and focuses the first enabled item. **Arrow Up** opens it and focuses the last item
- **Arrow Down / Arrow Up** move between items and wrap around. Disabled items are skipped
- **Home / End** jump to the first or last item
- Typing a character moves focus to the next item whose label starts with it
- Moving the mouse over an item focuses it
- **Enter** selects the focused item. **Space** selects buttons but not links. Selecting closes the menu and returns focus to the trigger, unless the item sets `closeOnSelect={false}`
- **Escape** or **Shift+Tab** closes the menu and returns focus to the trigger
- **Tab** closes the menu and moves focus to the next element after the trigger
- Clicking outside closes the menu

### Screen Readers

- The menu uses the `menu` ARIA role, and each item uses `menuitem`
- Screen readers skip icons and read only the item's text
- Make the text say everything the icon shows. For example, if an arrow icon means the link opens a new tab, add "(opens in a new tab)" to the label
- Menu sets `aria-haspopup`, `aria-expanded`, and `aria-controls` on the trigger
