# ToggleGroup

ToggleGroup is a set of joined toggles for switching between options in place, such as filtering a
schedule to **All Games**, **Past** or **Upcoming**. In Figma it's the **segmented control**.

- **`type="single"`** (default): exactly one item is selected. It behaves as a radio group.
- **`type="multiple"`**: any number of items can be selected, including none. It behaves as a group
  of checkboxes.

Selected items use the same fill as the brand `filled` [Button](/docs/actions-button--docs), so they
follow the active brand and color scheme. The color isn't configurable.

**Web only.**

## Anatomy

1. **Container**: a rounded, bordered row. 1px dividers separate the items.
2. **Item**: a label, an icon plus a label, or an icon alone. A label can include inline secondary
   content, such as a result count.
3. **Selected item**: filled with the brand fill.

## Usage

- Use it to switch between a few short, related options (two to five) that change what's shown in
  place. For navigating between pages or content panels, use tabs or links
- Keep labels short (one or two words) so the group fits on one line. On narrow screens it scrolls
  sideways rather than wrapping
- Give every group an accessible name: `label`, or `aria-labelledby` pointing at a visible heading
- Always controlled: pass `value` and `onChange`. With `type="multiple"`, `value` is an array
- Use `fullWidth` to fill the container and split it evenly, e.g. in a narrow card or panel
- For choices inside a form with longer labels or descriptions, use
  [RadioGroup](/docs/forms-formcontrol-radiogroup--docs) or
  [CheckboxGroup](/docs/forms-formcontrol-checkboxgroup--docs) instead

```tsx
function GameFilter() {
  const [filter, setFilter] = useState('all');

  return (
    <ToggleGroup.Root label="Filter games" value={filter} onChange={setFilter}>
      <ToggleGroup.Item value="all">
        All Games <span className={styles.finePrint}>(48)</span>
      </ToggleGroup.Item>
      <ToggleGroup.Item value="past">
        Past <span className={styles.finePrint}>(30)</span>
      </ToggleGroup.Item>
      <ToggleGroup.Item value="upcoming">
        Upcoming <span className={styles.finePrint}>(18)</span>
      </ToggleGroup.Item>
    </ToggleGroup.Root>
  );
}
```

### Secondary content

Item content is laid out on one baseline with a 6px gap, in the item's label typography. Style any
secondary content yourself, and color it with `--toggle-group-item-secondary-text`: it's the
tertiary text color on unselected items and a softened version of the selected text color on
selected ones, so it stays readable on either fill.

```scss
.finePrint {
  font-size: 14px;
  font-weight: 400;
  color: var(--toggle-group-item-secondary-text);
}
```

Keep it short and inline (a count, a version, a qualifier). Everything in the item becomes its
accessible name, so write it to make sense read aloud.

### Icons

Put icons from `@/icons` in the children, like text. They take the item's text color, so they read
on the selected fill too. The item sizes them to match its text, so leave off `size`.

An icon-only item has no text, so give it an `aria-label`. In development, an item with neither text nor `aria-label` logs a
warning.

```tsx
<ToggleGroup.Root label="View" value={view} onChange={setView}>
  <ToggleGroup.Item value="list" aria-label="List view">
    <MenuStackedIcon />
  </ToggleGroup.Item>
  <ToggleGroup.Item value="calendar">
    <CalendarIcon />
    Calendar
  </ToggleGroup.Item>
</ToggleGroup.Root>
```

Use icon-only items only when the icons are familiar in context (view modes, sports). Otherwise
add a label.

## Accessibility

Each item is a native radio (`single`) or checkbox (`multiple`) input under a styled label, so the
browser provides the keyboard and screen reader behavior:

- **`single`**: the group is one Tab stop; arrow keys move the selection between items
- **`multiple`**: every item is a Tab stop; Space toggles it
- Items are announced with all of their content, e.g. "All Games (48), radio button, checked, 1
  of 3"
