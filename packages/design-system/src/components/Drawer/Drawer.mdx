# Drawer

Drawer is a modal panel attached to an edge of the viewport. Use it for supplementary work that
belongs next to the page rather than in the middle of it — filtering a list, reviewing details, or
editing settings for what's on screen. It slides in from the **left** or **right** as a
full-height panel, or drops from the **top** or rises from the **bottom** as a sheet.

By default a drawer is a side panel on the right on desktop and a
bottom sheet on phones.

**Web only.** It relies on portals and CSS media queries.

**Validated for Varsity only.** Using it on `startribune-web` may warrant some theming changes.

## Anatomy

1. **Overlay** — Dims the page, blocks interaction underneath, and locks page scroll.
2. **Panel** — The surface: full height on the left or right edge, or a sheet on the top or
   bottom edge. At 767px and below, the top and bottom sheets round the corners on their open
   edge; every other placement is square.
3. **Close button** — Top-right X icon button. Hide it with `showCloseButton={false}`.
4. **Heading** — Names the drawer
5. **Body** — Main content. The only region that scrolls; its top edge fades out once content has
   scrolled above it, and its bottom edge fades out while more content sits below the fold.
6. **Footer (optional)** — Actions on one row, each sized to its label and sharing the leftover
   space. Labels never wrap; if the actions don't fit side by side, they stack.

For contextual, non-blocking content next to a control, use
[Popover](/docs/feedback-status-popover--docs) instead.

## Usage

- Give every drawer an accessible name: a `Drawer.Heading`, or `aria-label` when there is no
  visible title
- Put the primary action **last** in `Drawer.Footer`, so it sits at the end of the row and last in
  tab order
- The drawer is always controlled: pass `open` and `onClose`. The X icon button, Escape and
  overlay presses call `onClose`; footer actions close it by setting `open` to `false`
- Give `Drawer.Footer` an action that closes the drawer, such as "Done" or a primary action that
  applies and closes
- Don't nest drawers, and don't open one on page load

### Filter drawers

- Apply filters from an explicit footer action ("Show 999 Athletes") rather than on every change,
  so the page underneath doesn't reflow behind the overlay
- Put the result count in the primary button's label. It's announced when the user reaches the
  button; don't add a live region that announces every checkbox change
- Offer a "Clear All" action next to it

## Example

```tsx
const [open, setOpen] = useState(false);

<Button onClick={() => setOpen(true)}>Filter calendar</Button>

<Drawer.Root open={open} onClose={() => setOpen(false)}>
  <Drawer.Heading>Filter Calendar</Drawer.Heading>

  <Drawer.Body>{/* filter groups */}</Drawer.Body>

  <Drawer.Footer>
    <UtilityButton label="Clear All" onClick={clearAll} />
    <Button color="brand" onClick={() => setOpen(false)}>
      Show {count} Athletes
    </Button>
  </Drawer.Footer>
</Drawer.Root>
```
